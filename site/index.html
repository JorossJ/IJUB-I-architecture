IJUB Architecture

A 12-bit accumulator processor implemented in Verilog for the Intel Cyclone IV EP4CE6

Overview

IJUB is a simple custom processor you program by hand using DIP switches. You enter each instruction one at a time, save it into memory, then flip a switch to run the program.

All math and logic goes through one register called the accumulator (w_reg). It is 8 bits wide, so it holds values from 0 to 255.

Instruction width12 bits (4-bit opcode + 8-bit operand)
Accumulator (w_reg)8 bits — holds values 0–255
Instruction memory (I_SRAM)16 slots × 12 bits
Data memory (D_SRAM)16 slots × 8 bits
Total instructions16 (opcodes 0–15)
Clock speeds50 MHz (full speed) or 1 Hz (one step per second)
ArchitectureSingle-cycle — every instruction finishes in one clock cycle

Hardware Map

The processor uses all 16 DIP switches on your PCB and 2 buttons on the FPGA dev board.

DIP Switches

SwitchSignalWhat it does
SW[11:0] input_block The 12-bit instruction you want to enter. Set the top 4 bits to the opcode and the bottom 8 bits to the operand before saving.
SW[12] mode 0 = Program mode (enter instructions). 1 = Run mode (execute program).
SW[13] speed 0 = Full speed (50 MHz). 1 = Slow mode (1 Hz — one instruction per second, good for debugging).
SW[14] save Flip this to write the current input_block into the next instruction memory slot. Each flip saves exactly one instruction.
SW[15] rst Reset. While ON, the processor holds PC, accumulator, and all flags at zero. Also resets the program write pointer and browse pointer.

FPGA Dev Board Buttons

ButtonSignalWhat it does
BTN0 browse_next In program mode: move the browse pointer forward. The LEDs show the instruction stored at that slot and its address.
BTN1 browse_prev In program mode: move the browse pointer backward.

LEDs

All 16 LEDs are driven by output_block. In program mode they show the browsed instruction slot. In run mode they update when the OUT instruction executes. See Output Format for the bit layout.

Operating Modes

Program Mode SW[12] = 0

Use this mode to load your program into instruction memory. The processor is paused — the program counter is held at 0 and nothing executes.

To enter an instruction:

  1. Set SW[11:8] to the 4-bit opcode of the instruction you want.
  2. Set SW[7:0] to the 8-bit operand.
  3. Flip SW[14] (save). The instruction is written to the current slot and the write pointer advances automatically.
  4. Repeat for the next instruction.

To read back what you stored: Press BTN0 or BTN1 to scroll through slots. The LEDs show the instruction at the current browse position and its address.

Note
The save switch goes through a 10ms debounce filter and an edge detector, so each flip writes exactly one instruction — no matter how long you hold it.

Run Mode SW[12] = 1

The processor fetches and executes instructions from memory starting at address 0. The program counter (PC) advances by 1 each cycle by default. Jump instructions change this.

  1. The processor reads the instruction at I_SRAM[pc].
  2. It decodes the opcode (top 4 bits) and operand (bottom 8 bits).
  3. It executes the instruction and updates PC.
  4. Repeat from step 1.
Tip
Set SW[13] = 1 to run at 1 Hz while debugging. You can watch each instruction execute one at a time on the LEDs.

Reset SW[15]

Flip SW[15] ON at any time to reset the processor. While it is ON:

  • PC is held at 0
  • The accumulator (w_reg) is cleared to 0
  • All flags are cleared
  • The write pointer and browse pointer reset to slot 0

Flip it back OFF to resume normally.

Instruction Format

Every instruction is 12 bits wide and is split into two parts:

Bits [11:8]
OPCODE (4 bits)
Bits [7:0]
OPERAND (8 bits)

The opcode selects which operation to run (0–15). The operand is the value or address the instruction uses. For memory-addressing instructions, only the lower 4 bits of the operand are used as the address (operand[3:0]), since both memories only have 16 slots.

Example
To encode LDI 10 (load the value 10 into the accumulator): opcode = 0001 (1 in binary), operand = 00001010 (10 in binary). Full 12-bit instruction = 0001_0000_1010. Set SW[11:8] = 0001, SW[7:0] = 00001010.

Instructions

There are 16 instructions total. The accumulator is referred to as w_reg throughout.

  • opcode 0 NOP No Operation

    Does nothing. The processor simply advances to the next instruction. Useful as a placeholder or timing gap.

    — (operand ignored)
    Flags affected: none
  • opcode 1 LDI Load Immediate

    Loads a number directly into the accumulator. The number comes from the operand field of the instruction.

    w_reg ← operand
    Flags affected: none
  • opcode 2 LD Load from Memory

    Reads a value from data memory (D_SRAM) at the given address and puts it in the accumulator.

    w_reg ← D_SRAM[operand[3:0]]
    Flags affected: none
  • opcode 3 ST Store to Memory

    Writes the accumulator's current value into data memory at the given address.

    D_SRAM[operand[3:0]] ← w_reg
    Flags affected: none
  • opcode 4 CMP Compare

    Compares the accumulator with the operand and sets the flags accordingly. Does not change the accumulator. Use this before a conditional jump (JZ, JLT, JGT).

    compare w_reg with operand → set zf, lt, gt
    Flags affected: zf lt gt
  • opcode 5 JMP Jump (Unconditional)

    Jumps to a specific instruction slot, always. The address comes from the lower 4 bits of the operand. Use this to create loops.

    pc ← operand[3:0]
    Flags affected: none
  • opcode 6 JZ Jump if Zero

    Jumps to the target address only if the zero flag (zf) is set — meaning the last CMP found the accumulator equal to the operand. Otherwise, advances normally.

    pc ← (zf == 1) ? operand[3:0] : pc + 1
    Flags affected: none
  • opcode 7 JLT Jump if Less Than

    Jumps to the target address only if the less-than flag (lt) is set — meaning the last CMP found the accumulator less than the operand. Otherwise, advances normally.

    pc ← (lt == 1) ? operand[3:0] : pc + 1
    Flags affected: none
  • opcode 8 JGT Jump if Greater Than

    Jumps to the target address only if the greater-than flag (gt) is set — meaning the last CMP found the accumulator greater than the operand. Otherwise, advances normally.

    pc ← (gt == 1) ? operand[3:0] : pc + 1
    Flags affected: none
  • opcode 9 ADD Add

    Adds the operand to the accumulator and stores the result back in the accumulator. If the result exceeds 255, it wraps around and the carry flag is set.

    w_reg ← w_reg + operand
    Flags affected: cf
  • opcode 10 SUB Subtract

    Subtracts the operand from the accumulator. If the result goes below 0, it wraps around and the borrow flag is set.

    w_reg ← w_reg − operand
    Flags affected: bf
  • opcode 11 AND Bitwise AND

    Performs a bitwise AND between the accumulator and the operand. Each bit of the result is 1 only if both corresponding bits were 1.

    w_reg ← w_reg & operand
    Flags affected: none
  • opcode 12 OR Bitwise OR

    Performs a bitwise OR between the accumulator and the operand. Each bit of the result is 1 if either corresponding bit was 1.

    w_reg ← w_reg | operand
    Flags affected: none
  • opcode 13 NOT Bitwise NOT

    Flips every bit in the accumulator. 0s become 1s and 1s become 0s. The operand is ignored.

    w_reg ← ~w_reg
    Flags affected: none
  • opcode 14 XOR Bitwise XOR

    Performs a bitwise XOR between the accumulator and the operand. Each bit of the result is 1 if the corresponding bits were different.

    w_reg ← w_reg ^ operand
    Flags affected: none
  • opcode 15 OUT Output

    Sends the current accumulator value and all flags to the 16 output LEDs. This is the only way to see what the processor has computed.

    output_block ← {cf, bf, gt, lt, zf, 000, w_reg}
    Flags affected: none

Flags

Flags are 1-bit values that get set by certain instructions. They stay set until the next instruction that affects them. Conditional jump instructions (JZ, JLT, JGT) check these flags to decide where to go next.

FlagNameSet whenUsed by
zfZeroCMP finds w_reg == operandJZ
ltLess ThanCMP finds w_reg < operandJLT
gtGreater ThanCMP finds w_reg > operandJGT
cfCarryADD result exceeds 255 (overflows)OUT (visible on LED 15)
bfBorrowSUB result goes below 0 (underflows)OUT (visible on LED 14)
Important
CMP always sets exactly one of zf, lt, or gt and clears the other two. So you never have two of them set at the same time.

LEDs 15–11 show the processor flags. LEDs 10–8 are always off (unused). LEDs 7–0 show the accumulator value in binary — LED 7 is the most significant bit.

Reading the accumulator
LEDs 7–0 are the binary representation of w_reg. For example, if the accumulator holds 20 (binary 00010100), then LED 4 and LED 2 will be ON and all others OFF.

In program mode, the LEDs show the instruction stored at the current browse address (upper 12 bits) and the slot number (lower 4 bits).

Example Program

This program loads two numbers, compares them, adds one to the larger value, and outputs the result in an infinite loop.

; Slot   Opcode   Operand   What it does
; ────────────────────────────────────────────────────────
0        1        10        ; LDI 10  — load 10 into accumulator
1        3         0        ; ST  0   — store accumulator to D_SRAM[0]
2        1        15        ; LDI 15  — load 15 into accumulator
3        4        10        ; CMP 10  — compare 15 vs 10 → gt flag set
4        9         5        ; ADD 5   — accumulator = 15 + 5 = 20
5        15        0        ; OUT     — LEDs show: gt=1, w_reg=20
6        5         5        ; JMP 5   — jump back to slot 5 forever

How to enter this program:

  1. Set SW[12] = 0 (program mode) and SW[15] = 1 then back to 0 (reset write pointer to slot 0).
  2. For each row in the table, set SW[11:8] to the opcode and SW[7:0] to the operand.
  3. Flip SW[14] once to save the instruction. The write pointer advances automatically.
  4. Repeat until all 7 instructions are entered.
  5. Set SW[12] = 1 (run mode). The program starts from slot 0.
  6. The LEDs will show gt=1 (LED 13 ON) and the value 20 on LEDs 7–0.
Encoding reminder
Slot 0 (LDI 10): opcode = 0001, operand = 00001010 → set SW[11:8] = 0001, SW[7:0] = 00001010, then flip SW[14].

Verilog Modules

The design is made up of three Verilog modules:

ModuleDescription
ijub The top-level processor. Contains the clock divider, all memory and registers, the program mode logic, the run mode execute loop, and instantiates the submodules below.
debouncer Filters out mechanical noise from DIP switches. Waits for the signal to be stable for 500,000 clock cycles (~10ms) before passing it through. Parameterizable via STABLE_COUNT.
edge_detector Converts a steady level signal into a single 1-cycle pulse on the rising edge. This turns a DIP switch flip or button press into a one-shot event so only one action fires per flip.
